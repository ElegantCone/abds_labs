# Лабораторный проект

[![labs](https://github.com/ElegantCone/abds_labs/actions/workflows/energosbyt.lab.yml/badge.svg)](https://github.com/ElegantCone/abds_labs/actions/workflows/energosbyt.lab.yml)

Backend-сервис вымышленной ЖКХ-компании для практики по курсу «Архитектура систем обработки больших данных».

## Запуск проекта

Проект запускается с помощью Makefile и следующей последовательности команд:

```sh
make run
make setup
curl http://localhost:8080/ping
make teardown
make stop
```

| Команда         | Действие                                                                       |
|-----------------|--------------------------------------------------------------------------------|
| `make run`      | Собрать и поднять сервисы                                                      |
| `make stop`     | Остановить и удалить контейнеры, сохранить локальные данные ClickHouse         |
| `make gen`      | Создать CSV в `data/` отдельным запуском генератора в Docker                   |
| `make load`     | Проверить наличие CSV, удалить таблицы датасета, создать схему и загрузить CSV |
| `make setup`    | Последовательно выполнить `gen`, затем `load`; нужен запущенный ClickHouse     |
| `make teardown` | Удалить таблицы; базу оставить                                                 |

**`make load` и `make setup` заменяют содержимое таблиц данными из CSV.**
Повторная загрузка не создаёт дублей, поскольку перед импортом таблицы пересоздаются

## Конфигурация

Все параметры хранятся в `.env.local`:

- `APP_PORT` - порт приложения.
- `CLICKHOUSE_*` - специфичные настройки clickhouse.

Для запуска нужны Java 26 и переменные из `.env.local` в окружении процесса.

## HTTP API

Сервис работает без авторизации.
Коллекция для ручного запуска: [`api/postman_collection.json`](api/postman_collection.json).

| Запрос                                                              | Результат                                              |
|---------------------------------------------------------------------|--------------------------------------------------------|
| `GET /ping`                                                         | `200`, пустое тело                                     |
| `GET /users/{id}`                                                   | Объект; отсутствующий собственник — `404`              |
| `PATCH /users/{id}`                                                 | Изменение данных собственника; `204` без тела          |
| `GET /realty/{id}`                                                  | Объект отсутствующее здание — `404`                    |
| `POST /realty/{id}/readings`                                        | Добавление показания или корректировки; `201` без тела |
| `GET /realty/{id}/readings?date_from=2026-10-01&date_to=2026-10-31` | Актуальные показания и количество строк                |
| `GET /realty/{id}/invoices?limit=10&offset=0`                       | Страница счетов и общее количество счетов объекта      |
| `GET /tariffs?date=2026-10-27`                                      | Действующая версия тарифа с наименьшим подходящим `id` |
| `POST /realty/{id}/gauges`                                          | Установка или замена счётчика; `201` без тела          |

### Изменение собственника

Хотя бы одно из полей `fio` и `phone` обязательно.
`fio` не может состоять из пробелов, не должно быть явным null.
Телефон содержит `+` и 7–15 цифр, первая цифра ненулевая.
При отсутствии обоих полей возвращается `400`.

ФИО обновляется через SCD 1. При смене телефона прежнее значение
переходит в `phone_prev` (SCD 3); повтор того же номера не меняет `phone_prev`.

### Показания

Обязательны `user_id`, `gauge_id`, `tariff_id`, `reading_date`, `day_kw`, `night_kw`.
Числа передаются JSON-числами без дробной части. `day_kw` и `night_kw` находятся
в диапазоне UInt32. Дата имеет формат `YYYY-MM-DD`

Корректировка выполняется новым INSERT с тем же ключом

Если за дату есть разные счётчики, выбирается самое позднее `created_at`,
затем больший `gauge_id`.
Порядок дат в ответе - по возрастанию

### Счета и тарифы

`limit` и `offset` — неотрицательные целые числа, по умолчанию `10` и `0`.
Ответ содержит счета с указанными ограничениями и общее количество счетов без учета ограничений:
`{"invoices":[...],"count":N}`.
Сортировка — по убыванию `created_at`; при одинаковом времени используются
дополнительные поля для стабильной пагинации. `limit=0` возвращает пустую страницу.

### Установка счётчика

Тело: `{"gauge_id":2}`. Поле обязательно, должно быть неотрицательным целым числом.
При замене одним INSERT записываются копия старой строки с противоположным знаком и прежней версией, а также новая
установка с `sign=1`, `version=v+1`. Если активной установки нет, версия равна `1`.

## Схема ClickHouse

DDL находится в [`initdb/ddl`](initdb/ddl). Для таблиц выбраны следующие ключи сортировки и партиционирование:

| Таблица               | `ORDER BY`                            | Партиционирование и обоснование                                                      |
|-----------------------|---------------------------------------|--------------------------------------------------------------------------------------|
| `dim_realty`          | `(address, id)`                       | Нет: небольшой справочник; адрес группирует объекты одного дома                      |
| `dim_gauges`          | `(name, id)`                          | Нет: небольшой справочник; группировка по модели, id различает счётчики              |
| `dim_tariffs`         | `(id, valid_from)`                    | Нет: сохраняются разные интервальные версии одного тарифа                            |
| `dim_users`           | `id`                                  | Нет: одна актуальная строка собственника                                             |
| `fact_gauge_bindings` | `(gauge_id, realty_id)`               | Нет: установка и аннулирование одной версии могут схлопнуться                        |
| `fact_meter_readings` | `(realty_id, gauge_id, reading_date)` | `toYYYYMM(reading_date)`: месячные периоды и корректировки остаются в одной партиции |
| `fact_invoice`        | `(realty_id, created_at, gauge_id)`   | `toYYYYMM(created_at)`: чтение счетов объекта по времени и обслуживание по месяцам   |

## Генерация данных

`make gen` создаёт 7 CSV с заголовками в `data/` (папка исключена из git).
Для запуска нужны Java 26, указанная в Gradle toolchain, и `make`; Gradle запускается через Wrapper.
Seed равен 42.

Генератор создаёт 1000 помещений в 4 домах и по 1 собственнику
на помещение, 1100 счётчиков (включая 100 замен у случайно выбранных объектов),
1200 строк привязок, 3 тарифа с 7 версиями каждого и 36000 счетов.
Показания покрывают каждый день с 2023-11-01 по 2026-10-31;
около 3% дат имеют дополнительную корректировку с более поздним `created_at`.

Площади, ФИО, телефоны, модели счётчиков и даты записей различаются.
Потребление учитывает индивидуальный профиль помещения, сезонность и выходные.
Замены происходят 1 числа случайного месяца; накопленные показания нового
счётчика начинаются с 0. Счета выставляются в конце месяца по сумме суточного
расхода и действующей версии тарифа, срок оплаты — 10-е число следующего месяца.
